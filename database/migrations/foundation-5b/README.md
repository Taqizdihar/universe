Approved disposable database: **`uniin_universe_reh`**. The Aiven production database is `defaultdb`; the existing Kroombox development database is `uniin_universe`. Neither is an import target. All DDL in `02_rehearsal_schema.sql` names `uniin_universe_reh` explicitly, including foreign-key references. No database connection or migration runs automatically.

- A Kroombox phpMyAdmin screenshot verifies `InnoDB` and `utf8mb4_unicode_ci` for all five Foundation 2 metadata tables, whose table options were absent from the export.

The resulting [schema-only SQL](02_rehearsal_schema.sql) has 28 `CREATE TABLE`, 72 `ALTER TABLE`, and 24 named `CHECK` definitions. It creates no rows and contains no authentication values. The live metadata evidence applies to the five tables whose export definitions were incomplete; the original current Kroombox export and Foundation 4 inventory cover the other 23 tables.

## Manual phpMyAdmin sequence

1. Review the [isolation checklist](REHEARSAL_ISOLATION_CHECKLIST.md). Confirm `uniin_universe_reh` is a separate, empty, disposable database with no application consumer. Keep a restorable backup or an approved reprovisioning path. Do not point an existing service at it.
2. Select `uniin_universe_reh` in phpMyAdmin, open **SQL**, paste the complete [01_rehearsal_preflight.sql](01_rehearsal_preflight.sql), and click **Go**. Inspect `selected_context=uniin_universe_reh`, `schema_exists=1`, `existing_tables=0`, `preflight_status=PASS_EMPTY_REHEARSAL_SCHEMA`, and `schema_import_gate=READY_FOR_MANUAL_IMPORT_AFTER_PASS`. Any error or different value means **stop**. The breadcrumb alone is insufficient.
3. In the same phpMyAdmin SQL tab, paste the complete [02_rehearsal_schema.sql](02_rehearsal_schema.sql) and click **Go** once. It begins with `USE uniin_universe_reh` and qualifies every table and FK reference. It deliberately has no `IF NOT EXISTS`, `DROP`, `TRUNCATE`, or data-bearing DML. Stop on the first SQL error; do not rerun over a partially created schema or substitute `uniin_universe`.
4. After successful import, run read-only [03_rehearsal_verify.sql](03_rehearsal_verify.sql). Expect 28 base tables, all InnoDB with `utf8mb4_unicode_ci`, 212 columns, 25 auto-increment columns, 87 index parts, primary keys on all 28 tables, 30 foreign keys, 24 CHECK constraints, and **zero rows** in the cross-schema-FK result. Inspect the detailed column, key, FK-action, and CHECK output against the approved evidence, not just aggregate counts.
5. Run read-only [04_rehearsal_empty_data_check.sql](04_rehearsal_empty_data_check.sql). All 28 `exact_rows` values must be **0**. If any count or definition differs, stop and investigate. Do not auto-repair. Use the [restore/reset plan](RESTORE_AND_RESET_PLAN.md) for a partial import.

The read-only [source audit](00_development_constraints_audit.sql) and [metadata fallback](00b_development_structure_metadata.sql) remain available for independent recheck. The offline local export analyzer accepts `--source=/path/to/original.sql --live-check-csv=database/schema-evidence/foundation-5b/kroombox-live-checks-2026-11-13.csv`; it prints structural summaries only.

The structure preparation needs no website deployment. A future optional backend must be a **separate private service** with its own `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, and `DB_NAME=uniin_universe_reh` configured before first start. Disable Brevo, CDN writes/deletes, notifications, webhooks, and jobs first. Keep the existing development backend connection and all tenant-facing API URLs unchanged.

See the [synthetic bootstrap plan](SYNTHETIC_BOOTSTRAP_PLAN.md). A later data rehearsal still needs a protected Aiven snapshot fingerprint, identity maps for 19 legacy tables, protected Super Admin handling, reviewed Sentra Kreasi slug exceptions and API v1 detail behavior, optional Settings absence, media references, target-collation collision checks, and separately approved manual SQL. This package imports no tenant data and authorizes no production cutover.
